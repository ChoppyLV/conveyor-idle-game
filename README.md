# Line Balance (working title)

A mobile idle factory-puzzle game — Satisfactory's throughput-math satisfaction, minimized to 2D and a phone screen. Place production buildings on a grid, connect them with conveyor belts, and fix throughput bottlenecks. Backpressure makes jams visible; idle income accrues offline.

Built with plain HTML5 + Canvas + JavaScript (no build step, no dependencies) so it runs instantly in any browser and wraps to Android via Capacitor.

## Run it

Open `index.html` in a browser. That's it — it's fully self-contained. Progress autosaves to the browser (`localStorage`) and picks up where you left off, including catching up on offline earnings.

## What's here (Act 1 vertical slice)

`index.html` is the current playable slice, driven by the game's own recipe data:

- **Grid map** seeded with ore deposits — **fully invisible until scanned** (only one starter deposit is visible at boot). Select the **Scan** tool and drag a rectangle over the grid to reveal every deposit inside it (type, richness, exact position), permanently.
- **Buildings:** Extractor (goes on a discovered deposit — choose its tier, T1/T2/T3, at placement, tiers T2/T3 gated behind tech progress), Smelting Furnace, Fabricator (pick its recipe), Splitter (1→3), Merger (up to 3→1, same-good only), **Smart Splitter** (up to 3→3, DIFFERENT goods — see below), Storage Room (large inline buffer), Assembly Terminal (multi-good, multi-tier delivery goal), Generator (tap for power).
- **Splitter, Merger, and Smart Splitter can be spliced directly onto an existing belt** — place any of the three on a belt cell instead of an empty one and it splices in, cutting the belt into a before/after segment automatically, instead of requiring a standalone node wired up from scratch.
- **Strict ports, with one deliberate exception:** one belt per port, one port per distinct good — combine streams with a Merger, split with a Splitter. The Smart Splitter (unlocks at Tier 2) relaxes this on its input side only: it can hold up to 3 *different* goods at once (a Merger stays same-good-only), and lets you pick which buffered good each output belt should draw when you connect it — this is the scoped answer to "conveyors should carry multiple goods" that doesn't require rewriting the single-good belt model. If a Merger ever seems to "not work," it's almost always this: it's correctly refusing a 2nd input of a *different* good — reach for a Smart Splitter instead.
- **Belts are drawn manually, cell by cell** — two tiers, Belt T1 (3000/min, always available) and Belt T2 (6000/min, unlocks with tech progress). Tap a source building to arm it, then tap each adjacent empty cell in turn to lay the belt, then tap an adjacent destination to finish. Tap the last-placed cell again to undo it; re-tap the armed source with nothing drawn to cancel. Belts **cannot cross buildings or deposits** — you route around those by hand.
- **Elevator Overpass (unlocks at Tier 2):** while drawing a belt, tapping directly onto another belt's cell crosses over it instead of being rejected — a small purple crossing badge marks the spot. The belt underneath is completely undisturbed; both lines keep their full throughput, no penalty. Only one overpass may cross a given cell, and you can't splice a Splitter/Merger/Smart Splitter into a cell where a crossing exists. Below Tier 2, belts still can't cross at all — route around by hand until it unlocks.
- **Delete tool** — tap a building or a belt cell to remove it. Deleting a building cascade-deletes every belt still wired to it and frees up the ports on whatever it was connected to; deleting an extractor returns its deposit to a placeable (still-discovered) spot.
- **Tap a building with no tool selected** to open its info panel: recipe, live input/output buffers, utilization, power draw, and stall status, plus a **Delete** button and — for a Smelting Furnace/Fabricator — a **Change recipe** button that swaps its recipe in place (buffers reset to match) without tearing the building down. Recipe changes are blocked while any belt is still attached, so you don't strand goods mid-recipe; disconnect with the Delete tool first.
- **Tap the "Tier N · Name" label in the header** to open a tier-progress panel showing exactly what's still needed for the current tier, plus a preview of the next tier's requirements and unlocks.
- **Tech-tier progression:** deliver a bundle of finished goods to the Assembly Terminal to complete the current tier and unlock the next set of tools. **Tier 1 is a single good (30 Ferrite Plate)**, reachable from just the one starter deposit with a plain Extractor→Smelting Furnace→Fabricator chain — no Scanning, Splitter, or 2nd ore type needed — mirroring Satisfactory's own first HUB Upgrade (10x Iron Rod, one item, before copper is even reachable). It unlocks Splitter + Merger. **Tier 2** needs three goods from three different ores (Castcrete/Chalkstone, Ferrite Rod, Braided Cable/Cuprite) and unlocks Belt T2, Storage Room, Extractor T2, and the Smart Splitter — by this point you'll have Splitter/Merger to branch production and Scanning (always available, see below) to have found the other ore deposits. Tier 3 unlocks Extractor T3. Locked tools show disabled in the build palette; the extractor tier picker only offers tiers you've actually unlocked. **Scanning itself is never gated** — it's available from the very start, same as Satisfactory's Resource Scanner, specifically so you can never get stuck unable to find the ore a later tier needs. The turn-in schedule's shape is adapted from Satisfactory's own Milestone tree — the specific quantities are a placeholder pending a rebalancing pass.
- **Hybrid sim:** authoritative rate-based backpressure math with item sprites riding the belts. Overfeed a machine and the line backs up to a stalled source — exactly the bottleneck you have to solve. Every belt enforces its own tier's throughput cap.
- **Analyze panel** shows per-machine rate / utilization / buffers.
- **Save / offline earnings:** autosaves every 5s and on tab-close; reloading fast-forwards the same sim over real elapsed time (capped at 8h) and reports what you earned while away. A "New" button in the header clears the save (including Credits and Prestige level) and starts over.
- **Contracts:** two side quotas are always active (tap the **Contracts** tool to see them), each asking for a quantity of one specific good with a Credits reward. They don't compete with tech-tier delivery — a contract only claims a good's *surplus*, i.e. whatever you deliver to the Assembly Terminal above and beyond what the current tier still needs. Completing a contract pays out Credits and immediately rotates in a fresh one from a small hand-authored pool, so there are always two live. This reuses the Assembly Terminal rather than adding a new building — surplus that used to just sit unconsumed in the terminal's buffer now has somewhere to go.
- **Prestige:** once every currently-built tier is cleared, the **Prestige** button in the header lights up. Prestiging wipes the factory (deposits, buildings, belts, tier progress all reset, and you re-scan from scratch) but keeps your Credits and permanently boosts every future Extractor's rate by +10% per Prestige level, stacking across runs. It's deliberately separate from "New" — New wipes everything including Credits; Prestige is the deliberate progress-into-a-fresh-run loop. (Its unlock condition — clear all built tiers — is a placeholder standing in for a real capstone item once one exists.)

Play: tap **Scan** and drag over the map to reveal deposits → tap **Extractor** → tap a revealed deposit → pick a tier; add a **Smelting Furnace** and **Fabricator**; wire them together by tapping out a **Belt** cell by cell; deliver to the **Assembly Terminal** to unlock more tools. Tap any building with no tool selected to see what it's doing or change its recipe; tap the tier label to see what's left; check the **Contracts** panel for side quotas; use **Delete** to tear down and rewire; once every tier is cleared, **Prestige** for a permanent extractor-rate boost.

## Design notes

- Recipe **ratios and timings** are derived from Satisfactory's production tree and then re-skinned to original names/materials (grounded-industrial theme) — the mechanics are generic, the names/art are original. A single `RATE_SCALE` (×100) maps the source's small per-machine rates onto this game's 3000/min belt world while preserving every ratio.
- The tech-tier turn-in schedule (which goods gate which tier, which tools unlock together) is likewise adapted from Satisfactory's real Milestone tree, re-skinned and scaled down — an explicit placeholder for the numbers, not the system, pending a rebalancing pass.
- Full machine-readable dataset (100 materials, 204 recipes incl. alternates) lives in `data/line_balance_game_data.json` — the sim kernel is written to be driven by it, though the playable slice still uses a small hand-authored recipe subset day to day.
- Tunable constants are read from `window.__config` (storage cap, belt caps, richness, extractor multipliers, rate scale, battery, offline-earnings cap) so tests and balancing can override them.
- `window.__game` exposes a test API (`reset`, `place`, `connect` (an explicit path as its 4th arg, an optional forced-good as its 5th — only meaningful for a Smart Splitter's output, where the good can be ambiguous — and an optional per-cell crossing-flags array as its 6th, for Elevator Overpass), `tickN`, `node`, `state`, `deposits`, `findDeposit`, `scanRegion`, `discoverAll`, `tierUnlocked`, `TIERS`, `deliverToTerminal`, `deleteBuilding`, `deleteBelt`, `changeRecipe`, `cellPx`, `uiState`, `saveGame`/`loadGame`/`clearSave`, `CONTRACT_POOL`, `CONTRACT_SLOTS`, `doPrestige`, `prestigeEligible`, `prestigeMult`, `crossings`) — `state()` includes `contracts`/`credits`/`contractsCompleted`/`prestigeCount`/`prestigeMult`/`crossingCount`, and each belt in `state().belts` carries a `cross` array marking which of its path cells are overpass crossings — see `tests/regression.js` for how it's used, including driving the real pointer/canvas UI (not just the data model) for the belt-drawing tests.
- `prototypes/` holds earlier mechanic proofs, kept for reference.

## Tests

`tests/regression.js` is a headless Playwright suite (161 checks as of the last update) covering: build-palette sanity (every core building has a real, enabled button — added after a real bug where the Assembly Terminal's button silently went missing from the palette and no data-layer test caught it); the base chain; Splitter; Merger; Storage Room; extractor/belt tiers; Scanning; manual belt drawing (driven through the real pointer/canvas UI, not just the data API); belt splicing (Splitter and Merger spliced onto an existing belt); tech-tier gating end-to-end, including a softlock guard asserting Tier 1 stays a single good; save/load + offline earnings across a Tier 1 → Tier 2 progression; the Delete tool (both the data API and real taps, including port cleanup and cascade-delete); in-place recipe changes (blocked while connected, buffer reset on success); the building-info panel and tier-progress panel (real taps); the Smart Splitter, including a control case proving a Merger correctly refuses a 2nd input of a *different* good (almost certainly the source of the "mergers don't work" report) alongside the Smart Splitter accepting exactly that case; Contracts (pool/slot rotation, surplus-based fulfillment and Credits payout, and the real Contracts panel UI); Prestige (blocked until all tiers clear, factory wipe while keeping Credits, the extractor-rate multiplier, the New-Game-vs-Prestige distinction, the real header button including its `confirm()` dialog, and a save/load v3 round-trip through an actual page reload for Credits/contracts/Prestige level); and the Elevator Overpass (two independent belt lines crossing at one cell, both carrying real flow undisturbed; splicing blocked at a crossing but still working on normal cells; crossing cleanup on delete — including that deleting the *ground* belt under a crossing must leave the crossing intact; the Tier-2 gate blocking a crossing attempt pre-unlock through the real UI and allowing it after; and a save/load round-trip for the crossing registry and each belt's per-cell crossing flags). Run with `node tests/regression.js` — see `tests/README.md` for details (including how to get Playwright/Chromium set up). Worth running after any change to `index.html`'s sim, connection, or gating logic.
